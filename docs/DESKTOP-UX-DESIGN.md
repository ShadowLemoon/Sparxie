# Sparxie 桌面端 GUI / 触屏交互设计

> 状态：设计基线草案
>
> 目标：为 Sparxie 增加基于最新 WinUI 3 SDK 的桌面 GUI，同时保留现有 CLI；GUI 与 CLI 继续共享启动领域数据，界面层只保存自身的偏好与状态。

## 1. 产品定位

Sparxie 不是传统的“游戏门户”或“功能面板”，而是面向 Windows 触屏设备的极简启动器。

核心原则：

- **触屏优先**：三款游戏均以触屏初始化成功作为启动成功硬条件，界面中不存在“关闭触控”这一产品概念。
- **背景主视觉优先**：主界面 UI 尽量贴边、留白，避免遮挡背景主体。
- **启动路径最短**：切游戏、切 Profile、启动游戏都应在一到两次触摸内完成。
- **不重复信息**：游戏、Profile、设置、启动分别固定在一个位置，不在多个区域重复展示。
- **真实映射现有模型**：设置项直接对应 `GameProfile` / `HoyoProfileSettings`，不虚构 Runtime、账号、下载、存储等当前不存在的概念。
- **GUI / CLI 共用领域数据**：现有 `config.json` 继续作为启动配置真相源；主题、窗口尺寸等 GUI 专属偏好单独保存。

## 2. 信息架构

整个桌面端只保留三种主要界面状态：

1. **启动主页（Launch）**
2. **Profile 管理（Profiles）**
3. **应用设置 Side Panel（Application Settings）**

它们的职责严格区分：

- 顶部：切换游戏
- 左下：切换当前游戏的 Profile
- 右上：打开应用级设置
- 右下：启动游戏
- Profile 管理页：新增、删除、复制、编辑 Profile

### 2.1 主导航

顶部只平铺固定的三款游戏：

- 原神
- 崩坏：星穹铁道
- 绝区零

Profile 不放顶部，避免与游戏导航重复，也避免用户 Profile 增长后占满标题栏。

切换游戏时，GUI 应恢复该游戏上次使用的 Profile；若没有历史记录，则选择该游戏可用的默认 / 首个 Profile。

## 3. 启动主页

### 3.1 布局

```text
┌────────────────────────────────────────────────────────────┐
│ SPARXIE          原神   星穹铁道   绝区零      ⚙   ─ □ × │
│                                                            │
│                                                            │
│                     背景主视觉                              │
│                                                            │
│                                                            │
│ ┌────────────────┐                       ┌──────────────┐  │
│ │ PROFILE        │                       │   启动游戏   │  │
│ │                │                       └──────────────┘  │
│ │ 国服        ▾  │                                         │
│ │                │                                         │
│ │ 144 FPS        │                                         │
│ │ Unlock On      │                                         │
│ └────────────────┘                                         │
│ ● Ready                                                    │
└────────────────────────────────────────────────────────────┘
```

### 3.2 顶部游戏切换

顶部只展示游戏，不展示 Profile。

设计要求：

- 每个游戏入口都应具备足够大的触控命中区域。
- 选中态使用轻量 Acrylic / Mica 高亮，不使用过重的大块实色标签。
- 游戏切换不改变页面结构，只改变当前游戏、背景以及对应 Profile。

### 3.3 左下 Profile 卡

左下卡片只承担两件事：

1. 当前 Profile 快速切换入口
2. 当前 Profile 的少量启动摘要

不展示：

- 游戏名称（顶部已表达）
- 游戏路径（低频信息）
- 完整设置表单

推荐结构：

```text
PROFILE
国服                                  ▾

144 FPS      Unlock On
```

状态摘要不要求三个游戏强行保持同样数量。只显示当前游戏真正有价值的 1～2 项。

### 3.4 Profile 快速切换

点击左下 Profile 区域后，以大触控 Flyout 展开：

```text
Profiles

✓ 国服
  国际服
  144 FPS 配置

────────────────
＋ 新建 Profile
  管理 Profiles
```

原则：

- 整行可点，不要求用户精确点击小箭头。
- 每个条目最少使用约 56 px 行高。
- Flyout 从左下入口向上展开，避免撞窗口底部。
- 快速切换不进入编辑界面。

### 3.5 右下启动按钮

“启动游戏”是主页唯一的 Primary Action，固定在右下角。

原因：

- 给背景中心 / 右侧主体腾出空间。
- 触屏设备上容易形成固定肌肉记忆。
- 与左下 Profile、顶部游戏、右上设置形成四角稳定布局。

FPS 是重要配置，但不是视觉主角；主页不展示巨大的 FPS 数字。

### 3.6 游戏路径

游戏路径不属于主页一级信息。

仅在以下场景提升为一级：

- EXE 未配置
- 文件不存在
- 文件名不在对应游戏白名单
- 启动前验证失败

异常态示例：

```text
⚠ 找不到游戏
国服                                  ▾

[ 定位游戏 ]
```

## 4. Profile 管理页

Profile 管理是独立编辑模式，不叠加在主页，也不保留启动按钮。

### 4.1 布局

```text
┌────────────────────────────────────────────────────────────┐
│ ← Profiles                                                │
│                                                            │
│ ┌────────────────┐ ┌─────────────────────────────────────┐ │
│ │ + 新建         │ │ 编辑 Profile                        │ │
│ │                │ │                                     │ │
│ │ ● 国服         │ │ 名称                                │ │
│ │   144 FPS      │ │ 游戏路径                            │ │
│ │                │ │                                     │ │
│ │   国际服       │ │ FPS 解锁                            │ │
│ │   120 FPS      │ │ 目标 FPS                            │ │
│ │                │ │ 后台 FPS 限制                       │ │
│ │   触控配置     │ │ 后台 FPS                            │ │
│ │   400% UI      │ │ 进程优先级                          │ │
│ └────────────────┘ │                                     │ │
│                    │ 原神专属……                          │ │
│                    └─────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

### 4.2 左侧 Profile 列表

左侧承担：

- 选择 Profile
- 新建 Profile
- 复制 Profile
- 删除 Profile
- 查看未完成配置状态

触控要求：

- 每行 56～64 px 以上。
- 整行可点。
- 当前选中项要有清楚但不过重的高亮。
- 删除、复制等低频动作不常驻小图标，可放在选中项详情区或长按 / 右键菜单。

### 4.3 右侧 Profile 编辑器

右侧设置项直接映射现有模型。

#### 原神 / 星铁通用

- 名称
- 游戏可执行文件路径
- FPS 解锁
- 目标 FPS
- 后台 FPS 限制
- 后台 FPS
- 进程优先级

#### 原神额外

- 跟随游戏内 FPS 档位
- 30 FPS 档对应目标 FPS
- 60 FPS 档对应目标 FPS
- 覆盖触控 UI 缩放
- 触控 UI 缩放百分比

#### 绝区零

当前模型没有 Hoyo 设置，因此只显示 Profile 基础字段，例如名称与游戏路径。

不为了视觉对称显示无效或禁用的占位项。

### 4.4 数值与触屏控件

当前校验范围：

- FPS：10～1000
- 原神触控 UI 缩放：100%～500%

触屏优先时，数值调整不应依赖细 Slider。

推荐使用：

```text
目标 FPS
[ − ]        144        [ + ]
```

必要时可以在下方补充较粗的 Slider 用于快速拖动。

### 4.5 保存策略

默认即时保存，不设置全局“应用 / 保存 / 取消”三按钮。

路径等可能失败的字段在具体操作完成时做即时验证。

## 5. 应用级设置 Side Panel

右上角齿轮只代表 **Sparxie 应用级设置**，不用于编辑当前 Profile。

### 5.1 核心形态

设置采用从右侧覆盖主页的 **Side Panel / Drawer**，而不是设置整页，也不是将主页挤成左右分栏。

必须遵循以下口径：

- **Panel 是覆盖出来的，不是挤出来的**：打开设置时主页宽度、元素位置和背景构图保持不变。
- **主页仍然存在**：顶部游戏切换、左下 Profile 卡、右下启动按钮都留在原位置。
- **主页整体降权**：Panel 打开后，在主页上叠加半透明 Scrim，并对主页做轻微 Blur + 降亮。
- **Panel 自身保持清晰**：模糊只作用于 Panel 后面的主页，不作用于设置内容本身。
- **启动按钮仍存在但降权**：右下“启动游戏”不因为设置打开而消失，只降低亮度、对比度或透明度，避免与 Panel 抢焦点。

推荐层级：

```text
最上层：Application Settings Side Panel（清晰）
中间层：Scrim + Backdrop Blur（降亮 / 模糊主页）
最底层：原始主页（不重排、不缩窄）
```

推荐宽度约 **420～520 px**。

### 5.2 开合与焦点行为

打开：

- 点击标题栏右上齿轮。
- Panel 从窗口右侧向左滑入。
- Scrim 与主页模糊 / 降亮同步淡入。
- 键鼠焦点与触屏操作焦点进入 Panel。

关闭：

- 点击 Panel 右上角关闭按钮；或
- 点击 Panel 外部的 Scrim 区域。
- Panel 向右滑出，Scrim 与背景模糊同步淡出。
- 关闭后恢复打开前的主页上下文，不重置当前游戏或 Profile。

设置打开期间：

- Scrim 下方主页不应继续接收普通点击，避免误启动或误切换。
- 主页保留可辨识度，让用户明确自己仍处于原来的启动上下文中。
- 不需要为了设置态隐藏主页控件；通过降亮和输入阻断完成焦点转移。

### 5.3 视觉口径

Panel 需要表现为“附着在主页上的侧边抽屉”，而不是一张新的设置页面：

- 使用 WinUI 3 / Windows 11 风格的 Mica / Acrylic 质感。
- Panel 边界要轻，可以有细边框、轻微阴影或极弱发光，但不要使用厚重分栏线。
- Panel 内部内容保持高可读性，背景透明度不能低到影响文字和控件识别。
- 页面大背景仍然是视觉主角；设置态只是临时把焦点提到右侧。
- 动画以短时滑入 + 淡入为主，不做大幅缩放或复杂过渡。

### 5.4 触屏要求

Side Panel 本身同样遵循触屏优先：

- 关闭按钮至少提供约 48 px 实际命中区域。
- 设置 Row 建议 56 px 左右或更高，并允许整行点击。
- Segmented / Radio 类选项要提供足够宽的触控区域，不依赖小圆点或小图标。
- Switch 所在 Row 可整体点击切换。
- 数据与诊断等导航行应整行可点，不要求精确点击最右侧箭头。

### 5.5 设置内容

第一版保持克制，只放真正属于 GUI / 应用层的设置。

#### 外观

- 主题：跟随系统 / 浅色 / 深色
- 背景表现：标准 / 柔和（如后续需要）

#### 启动器行为

- 游戏启动后的窗口行为：保持窗口 / 最小化 / 关闭窗口
- 启动时恢复上次游戏（如后续确定）

#### 数据与诊断

- 打开配置目录
- 查看日志
- 导出脱敏诊断信息

#### 关于

- Sparxie 版本
- 许可证
- 第三方声明
- Runtime Notice

### 5.6 不属于应用设置的内容

以下内容全部属于 Profile，不放应用设置：

- Profile 名称
- 游戏路径
- FPS 解锁
- 目标 FPS
- 后台 FPS
- 进程优先级
- 原神档位映射
- 原神触控 UI 缩放

同时不提供“启用触控”开关；触屏初始化是 Sparxie 的核心启动条件。

### 5.7 窄窗口适配

正常桌面尺寸优先保持右侧覆盖式 Side Panel。

当窗口宽度不足以同时保证 Panel 可读性和合理的剩余主页上下文时，可以降级为全宽 / 近全宽设置层；但依然保持“设置是临时覆盖层”的交互语义，而不是把它设计成一级导航页面。

## 6. 数据边界

现有共享启动配置继续保留在：

```text
config.json
├─ schemaVersion
├─ selectedProfileId
└─ profiles[]
```

这是 CLI 与 GUI 共用的启动领域数据。

GUI 专属偏好建议单独保存，例如：

```text
desktop.json
├─ theme
├─ windowSize
├─ launchWindowBehavior
├─ backgroundPresentation
└─ lastProfileByGame
```

这样保持边界：

- `config.json`：启动领域真相源，CLI + GUI 共用
- `desktop.json`：仅 WinUI 桌面端使用的界面偏好

`lastProfileByGame` 只用于提升 GUI 的切游戏体验；当前全局活动 Profile 仍应与共享 `selectedProfileId` 保持一致。

## 8. 触屏交互基线

建议整个 WinUI 端遵循以下触屏基线：

- 主要点击目标：约 48 px 以上命中区域。
- 列表项：56～64 px 以上。
- 不依赖只有 16～20 px 的小箭头 / 小图标作为唯一命中区域。
- 设置 Row 整行可点击。
- 设置齿轮可使用 36～40 px 可见尺寸，但实际透明命中区约 48 px。
- 设置按钮位于窗口三按钮左侧，与窗口控制留约 12～16 px 分组间距。
- 侧边面板关闭按钮同样应提供大命中区域。
- 避免细 Slider 作为唯一的数值输入方式。

## 9. WinUI 3 视觉方向

- Mica / Acrylic / Windows 11 Fluent Design。
- 深浅模式均需要支持，但主页视觉可按当前游戏背景自适应。
- 半透明、轻边框、低对比阴影，不堆叠大量“玻璃卡片套玻璃卡片”。
- 背景主元素优先，主页 UI 固定在顶部、左下、右上、右下。
- Settings Panel 打开时，仅背景主页降亮 / 模糊，Panel 自身保持清晰。
- Settings Panel 覆盖主页，不改变主页宽度和控件布局。
- Settings Panel 打开时 Launch 按钮仍保留，只做视觉降权，并由 Scrim 阻断误触。
- 动画以短时淡入、滑入为主，不使用复杂夸张动效。

## 10. 非目标

当前桌面 GUI 设计不包含：

- 下载管理中心
- 账号中心
- 游戏新闻 / 活动门户
- 游戏时长统计
- 磁盘占用 Dashboard
- Runtime 管理 Dashboard
- GUI / CLI “同步状态”提示
- 关闭触屏功能

这些内容与 Sparxie 当前的产品定位和数据模型无关，不应为了让界面“看起来丰富”而加入。

## 11. 后续实现建议

桌面端建议新增独立 WinUI 3 Host（例如 `Sparxie.Desktop`），复用现有 `Sparxie.LauncherCore`，不要复制 CLI 业务逻辑。

实现顺序建议：

1. 搭建 WinUI 3 Host 与共享配置读写。
2. 实现主页游戏切换、Profile 快速切换和启动流程。
3. 实现 Profile 管理页，并一对一映射现有 Profile 字段。
4. 实现应用级 Settings Side Panel：`HomeContent + ScrimOverlay + AppSettingsDrawer` 三层叠加，确保主页不重排。
5. 增加触屏命中区域、焦点、键鼠 / 触控混合输入验证。
6. 最后再接入背景、动画与主题细节。
