# Sparxie 桌面端 GUI / 触屏交互设计

> 状态：与当前实现同步（2026-11）。本文描述桌面端**已经实现**的行为；尚未实现的内容集中写在最后一节“待办”。
>
> 目标：基于 WinUI 3 的桌面 GUI，面向触屏设备的极简启动器；启动配置与界面偏好存放在同一个 `config.json`。

## 1. 产品定位

Sparxie 不是传统的“游戏门户”或“功能面板”，而是面向 Windows 触屏设备的极简启动器。

核心原则：

- **触屏优先**：三款游戏均以触屏初始化成功作为启动成功硬条件，界面中不存在“关闭触控”这一概念。
- **背景主视觉优先**：界面尽量贴边、留白，不遮挡背景主体；主题色随背景图变化。
- **启动路径最短**：切游戏、切配置、启动游戏都在一到两次触摸内完成。
- **单配置时不出现“配置/Profile”概念**：大多数人每个游戏只有一套配置，界面上只有“游戏设置”；有多套（如国服/国际服）时才出现配置切换。
- **真实映射现有模型**：设置项直接对应 `GameProfile` / `HoyoProfileSettings`，不虚构不存在的概念。
- **数据合一**：只有一个 `config.json`：启动配置（schemaVersion / selectedProfileId / profiles[]）与可选的 `desktop` 段（界面偏好）同文件保存，没有单独的 GUI 配置文件。

## 2. 信息架构

只有三种界面状态：

1. **主页（Launch）**
2. **游戏设置页**（按游戏分开，一个游戏一页）
3. **应用设置抽屉**（覆盖式 Side Panel）

分工固定：

- 左下：**游戏卡**——同时承担“当前游戏 + 当前配置”的显示与切换，右侧齿轮进入当前游戏的设置；
- 右下：**启动游戏**（唯一主操作）；
- 右上：应用设置（圆形齿轮）；
- 顶部：只有窗口标题与系统窗口按钮，**没有游戏标签**。

## 3. 启动主页

### 3.1 布局

```text
┌────────────────────────────────────────────────────────────┐
│ ▷ Sparxie                                       ⚙   ─ □ × │
│                                                            │
│                       背景主视觉                            │
│                                                            │
│ ┌──────────────────────────┐                ┌────────────┐ │
│ │ [图标] 绝区零 · 国际服  ▴ │⚙│              │ 启动游戏 │ │
│ └──────────────────────────┘                └────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- **游戏卡**：固定宽度 380、高 68，半透明深色底（不用 AcrylicBrush：动态背景的视频是交换链渲染，应用内亚克力采样不到会变纯黑），圆角 20。左侧切换区显示游戏图标（40px）与文字，单配置时只写游戏名（“原神”），多配置时写“游戏 · 配置名”；右侧 68×68 的齿轮进入当前游戏设置。
- **启动游戏按钮**：320×68 的大胶囊，填充色取当前游戏背景主色的色相（柔色：饱和度约 0.42、明度约 0.97），深色粗体字；悬停变深一档（并按悬停色重新选字色以保证对比度），按下再深一档。
- **设置齿轮**：右上角 44px 纯图标按钮（无底无描边，悬停 / 按下才出现圆角淡底，和系统窗口按钮一个气质），位于系统窗口按钮左侧并留出间距。
- **启动状态条**：仅在“调试模式”下显示在启动按钮上方，列出启动/注入各阶段与失败原因；平时隐藏，失败原因仍写入日志。

### 3.2 游戏卡与切换 Flyout

点击游戏卡左侧切换区，向上展开 Flyout（宽 344，圆角 20，亚克力）：

- 三个游戏各占一个“块”：标题行（图标 + 名称，行高 56）；该游戏有**多套配置**时，标题下平铺配置按钮（高 48，胶囊）；单配置的游戏不显示配置按钮。
- **配色规则只有两种**：当前激活项用**主题色**（单配置游戏是整行，多配置游戏是对应的配置按钮），其余为灰色/描边；**不使用对勾**。
- 点击游戏标题 = 切到该游戏**上次使用的配置**（记住的配置在 Flyout 里以浅灰底提示，保证点之前就能预见结果；记忆保存在 `config.json` 的 `desktop` 段，重启后保留，没有记录时取该游戏第一套配置）。点击某个配置按钮 = 同时切游戏和配置。
- **切换后 Flyout 保持打开**，方便连续比较并观察背景与主题色的变化；点 Flyout 外部或按 `Esc` 关闭。

### 3.3 背景与主题色

- 背景来自官方启动器接口（HoYoPlay `getAllGameBasicInfo` 的 backgrounds），按**图片 URL 的哈希**命名缓存到 `cache/backgrounds/`，并记录每个游戏“当前背景”指针；官方换图即换文件名，不覆盖旧文件。
- 切换游戏时**先同步显示缓存**，再在后台检查官方是否换图；官方地址在内存中缓存 10 分钟；网络失败回退该游戏上次的缓存，再没有则退回纯色背景。
- 切换时新图叠在旧图上交叉淡入（约 450ms）。
- **主题色**：取背景图的平均色，保留其色相与明度（V），饱和度固定 0.6；平均色接近无彩色时回退默认蓝。主题色驱动激活项、启动按钮，并覆盖系统强调色（`SystemAccentColor` 及亮/暗变体），其他强调色控件随之变色。暗背景得到偏暗的主题色，亮背景才亮。

### 3.4 游戏路径异常与运行状态

- **路径异常**：当前配置的 EXE 未设置、找不到文件、文件名不属于该游戏时，启动按钮上方出现提示条（黄色描边），并带“定位游戏”按钮，直达当前游戏的设置页。检查规则与设置页、配置域层一致（`ExecutablePathCheck`）。
- **运行状态**：会话启动成功后，该游戏的启动按钮禁用并显示“运行中”；收到终态事件（退出 / 失败 / Host 崩溃）后恢复。启动过程中显示“启动中…”。按游戏区分，其他游戏仍可启动。
- 已知边界：桌面端重启时不会检测此前已在运行的游戏，按钮仍可点，点了会被会话边界以“对应游戏已在运行”拒绝。

## 4. 游戏设置页

设置页**按游戏分开**，标题为“{游戏} 设置”，左上是带文字的“‹ 返回”玻璃胶囊（在页面内容区，不在标题栏；`Esc` 同样返回）。

### 4.1 布局

两栏，宽度全程拉伸，不因折叠、切换配置或切换游戏而改变：

```text
┌ ‹ 返回  原神 设置 [配置A][配置B]            ＋ 添加配置 ┐
│ ┌ 游戏 ──────────┐ ┌ 帧率 ────────────────────────┐ │
│ │ 名称（多配置时）│ │ 目标帧率            [开关][−120+]│ │
│ │ 游戏 EXE  [📁] │ │ 后台帧率            [开关][−10 +]│ │
│ │ 进程优先级      │ │ 帧率档位映射（原神）           │ │
│ └────────────────┘ └──────────────────────────────┘ │
│ ┌ 触控 UI 缩放（原神）┐                                │
│ （没有保存条；修改后自动保存，出错时底部浮出提示） │
└──────────────────────────────────────────────────────┘
```

- **左栏（固定 380）**：游戏相关——名称（仅多配置时显示）、游戏 EXE（带浏览）、进程优先级，以及“启动设置”卡（见 4.3.1）。
- **右栏**：帧率卡 + 原神的“触控 UI 缩放”卡（叠在帧率卡下面）。帧率的开关与数值合并为一行；开关关闭时只**禁用**对应数值，不隐藏，因此高度宽度都不变；原神多一行“帧率档位映射”（跟随游戏内档位 + 30/60 档数值）。
- **响应式**：按面板实际宽度切换——够宽（≥ 约 980 DIP）时左 380 | 右 * 两栏；不够宽时折成单列，右栏接到左栏下面。不用窗口宽度的 AdaptiveTrigger（受 DPI 缩放影响，会在默认窗口大小下误触发）。
- **绝区零**没有帧率与优先级设置：只显示一张铺满宽度的“游戏”卡（名称、EXE），不留空的右栏。
- **配置 ID 不在界面出现**，新建时自动生成不重复的 ID。

### 4.1.1 游戏 EXE：自动查找 + 浏览

游戏 EXE 输入框右侧有两个按钮：**自动查找**（放大镜）和**浏览**（文件夹）。自动查找按下面的来源收集候选（都只收文件存在、文件名在该游戏白名单里的本机盘符路径），再选出要填的那一个：

1. 米哈游启动器（HYP）在 HKCU 登记的 `GameInstallPath`（同 Starward，能认出服务器）；
2. 卸载项里该游戏启动器 / 旧版的安装目录（在其下 ≤3 层找 EXE）；
3. Windows 记录的“最近运行过的程序”（MuiCache、兼容性助手）：手动解压 / 没有启动器登记的安装靠它找回，服务器只能靠 EXE 名（原神 YuanShen = 国服、GenshinImpact = 国际服）或目录名里的 `_cn` / `global` / `bilibili` 提示判断；
4. 正在运行的同名游戏进程。

**选取规则**：跳过已经被现有配置（含当前这套）使用的路径，剩下的按 **国服 → B 服 → 认不出服务器 → 国际服** 排序。只剩一个就直接填入；**有多个就弹窗列出（路径 + 来源），默认选中排第一的，由用户选一个**，取消则什么都不改，不做循环 / 轮换；找到的都已经加到配置里了，就提示“没有找到新的…：找到的 N 个安装都已经添加到配置里了”；完全没找到则提示手动选择。填入后照常自动保存。

**Steam 版（仅绝区零）**：EXE 所在目录有 `steam_appid.txt` 就按 Steam 安装处理，名称识别为“Steam”，启动时不直接运行 EXE，而是请求 `steam://run/4162040//<转义后的启动参数>`，再等 Steam 拉起新的游戏进程（按路径匹配、忽略请求前已存在的进程，最长等 5 分钟，会话取消即停止），之后照常注入触屏 Runtime。要求 Steam 与本程序权限级别一致（本程序以管理员运行时，Steam 也要以管理员运行，否则可能拉不起来或注入失败）。做法参照 ZZZTouchLauncher。

### 游戏背景

- 取官方启动器（HoYoPlay）接口里该游戏的**全部**背景，不只第一张；图片下载到本地缓存，离线时用上次的列表；另外和 Starward 一样，把启动器的**游戏海报**（getGames → display.background）追加为最后一张静态背景（绝区零因此有 2 张）。
- 官方背景不止一张（或当前是动态背景）时，**窗口底边**有一条渐变带（布局同 Starward），**鼠标移到底部才淡入**，里面居中是一排圆点（当前那个实心），动态背景旁边带暂停 / 播放键；点圆点或在底部滚轮切换，选择按游戏记住；只有一张静态背景时不出现。
- 带视频的背景是**动态背景**：静音循环播放，盖在静态图上（视频打开前和失败时仍显示静态图）。圆点旁边有暂停 / 播放键：**暂停 = 切回这张动图对应的静态图**（视频层隐藏并停止解码），再点恢复播放，暂停状态切换背景后保持。主窗口**完全不可见**（最小化或隐藏到托盘）时自动暂停播放，窗口回来继续。视频约十几 MB，选中后才后台下载。
- **标题叠加图（theme）**：视频类背景的接口里带一张透明的标题 / Logo 图，和图片、视频同一画幅。**静态图、视频、叠加图放进同一个 16:9 画幅（都 Fill 到同一矩形），再由一个 Viewbox 统一居中缩放裁剪**，三层共用同一个锚点，所以不管窗口怎么变、怎么裁，位置都严格对齐；叠加图盖在它们上面，没有叠加图的背景不显示。
- **淡入淡出**：切换背景、标题叠加图换成新的、底部切换条出现 / 消失，都有渐变，不硬切。视频层本身**不做透明度动画**（视频控件是交换链渲染，改透明度会闪黑），视频的出现 / 暂停 / 恢复都靠视频上方一张同样的静态图“遮罩”淡入淡出完成。
- **两个动态背景之间切换**（换游戏 / 换圆点）：旧视频 → 新海报（遮罩淡入完全盖住）→ 换视频源 → 新视频打开后遮罩淡出，是连续渐变；应用启动后动态背景自动播放，不需要手动点一下。
- **切换条不抖动**：暂停键位置始终占位（静态背景时透明、点不到），在有 / 没有暂停键的背景之间切换时，圆点位置不动。
- 视频是 WebM（VP9），系统没有对应解码器（Windows 的 VP9 视频扩展）时播放失败，自动退回静态图。

### 文字原则

界面上**不写复述控件本身的说明**：标题已经说清楚的开关、下拉、数值框不加副标题（范围由控件限制），按钮已有文字的不加同义悬停提示（仅纯图标按钮保留，用于无障碍），成功操作不弹“已保存 / 已填入”之类的提示，空状态不放“没有…”的占位文字。只在**出错、或确实有歧义且用户无法自己判断**时才出文字。例外：**原神的“触控 UI 缩放”保留一行说明**——它是向游戏注入“感知到的桌面 DPI”，主要用来调整方向键大小，名字看不出来。


### 4.2 多配置

- 只有一套配置时没有任何列表，页面就是一张表单。
- 同一游戏有多套时，标题行出现**横向配置切换条**。
- 标题行右侧常驻“＋ 添加配置”，点击**立即创建并保存**一套新配置（自动取不重复的 ID 与名称），随后在表单里补全。
- 标题行右侧“⋯”菜单：**复制当前配置**（复制路径与全部设置，名称加“副本”，立即保存）；**删除当前配置**（仅多配置时出现，点击先弹确认），不再占用表单位置。
- 一个游戏的最后一套配置不可删除（避免出现空配置）。

### 4.3 数值与触屏控件

- FPS：10～1000；原神触控 UI 缩放：100%～500%。
- 数值一律用 `[−] 值 [+]` 控件（按钮 48×48，数值框 18 号字、垂直居中），不依赖细 Slider。
- 文本框、下拉框统一 16 号字、最小高度 48、文字垂直居中。

### 4.3.1 启动设置（分辨率 / 全屏 / 无边框 / 附加参数）

左栏“游戏”卡下面的“分辨率”卡（三款游戏都有），每个配置独立保存，沿用自动保存。控件对齐 Starward 的“分辨率”区：

- **总开关“启动时覆盖游戏的分辨率与全屏（退出后恢复）”**（默认关）：开启后，每套配置存的一套分辨率 + 全屏会在**触屏启动前备份游戏原值并写入游戏注册表，游戏进程退出后恢复备份值**，键鼠启动（官方启动器、Starward）看到的还是原来的设置，互不影响；关闭时完全不碰游戏自己的设置。开关关闭时，全屏 / 自定义分辨率 / 分辨率下拉 / 宽高**联动禁用**；“使用无边框窗口”走命令行参数，不受开关影响，放在开关上面。只存了全屏没存分辨率时，宽高用 1920×1080。备份同时落盘（`recovery\registry-backup-<游戏>.json`），进程被强杀 / 断电后，下次启动前先恢复遗留的备份。
- **全屏**、**自定义分辨率** 复选框；**使用无边框窗口** 复选框（与是否全屏无关，同 Starward）；
- **分辨率下拉**：Starward 的常用分辨率列表中不超过主显示器的，加上主显示器本身，**并固定钉上 4K（3840×2160）/ 2K（2560×1440）/ 1080p（1920×1080）**（小显示器上也始终在列表里），从大到小；勾选“自定义分辨率”后下拉置灰、改用**宽 × 高两个输入框**（朴素的数字框，**没有加减按钮**，640×480 – 16384）；
- **附加启动参数**：单行文本，原样追加到命令行（≤512 字符，不能含换行等控制字符）；下方显示“最终命令行预览”。
- 全部是“不修改 / 关闭”时配置里不保存 `launch` 段。

生效方式（参考 Starward 的两条链路，但合在一处）：
1. **分辨率 + 全屏 → 写游戏自己的注册表设置**（总开关开启时；启动前备份原值，游戏退出后恢复）：启动前由 SessionHost 写 `HKCU\Software\miHoYo\原神 / Genshin Impact`、`…\崩坏：星穹铁道`、`Cognosphere\Star Rail`、`…\绝区零`、`…\ZenlessZoneZero` 下的 `Screenmanager …` 键（星铁另有 `GraphicsSettings_PCResolution` JSON）。只写**已存在**的键（游戏没运行过就没有键，本次跳过并在 Starting 事件里说明）；星铁 / 绝区零国服与国际服 EXE 同名：**先像 Starward 那样现场读取米哈游启动器（HYP）在 HKCU 里登记的 `GameInstallPath`**，EXE 恰好落在某个服务器的安装目录下就只写那个服的键；认不出（没有登记，如手动解压的安装）或两个都命中时，有几个键就都写。失败不阻止启动。
2. **使用无边框窗口 → 自动注入命令行参数 `-popupwindow`**（不看全屏与否）；用户在附加参数里已经写了就不重复，附加参数追加在其后。命令行参数由 SessionHost（绝区零）或 native bootstrap 的 `CreateProcessW`（原神 / 星铁，HoyoTouchCore ABI v2）传给游戏。

### 4.4 保存策略

**自动保存，没有保存按钮和未保存状态，也没有延迟 / 防抖**：每次“提交”立刻落盘。对应 Qt 的 editingFinished：

- 开关、复选框、下拉框、数值框（回车 / 失焦 / 点上下箭头）：一次操作就是一次提交，立即保存；
- 文本框（名称、路径、附加启动参数）：**失去焦点或按回车时**才提交并保存，输入过程中不写盘；直接点配置标签时，标签栏在按下的瞬间先抢走焦点，让输入框先提交，避免“输入完直接切标签，没存上”。

- **配置名称不预设区服**：新建配置（含第一套占位配置）叫中性的“配置 1 / 配置 2…”。填入游戏路径后（自动查找、浏览、手输都算），如果名称还是自动生成的（“配置 N”，或旧版本预填的 国服 / 国际服 / B 服 / Steam，可带序号），就按识别到的区服改名；同一游戏里重名加序号（“国服 2”）。用户自己起的名字不会被改，认不出区服时名称不变。
- **区服识别依据**（`ServerLabelDetector`，按可靠程度）：EXE 同级或上一级目录 `config.ini` 的 `game_biz`（再看 `cps` / `channel=14`）→ 米哈游启动器登记路径 → 原神 EXE 名（YuanShen = 国服、GenshinImpact = 国际服）与目录名提示。自动查找弹窗里每个候选前面也标出识别到的区服。
- **保存成功不提示**（路径框 / 控件本身就是反馈）；只有失败（如路径不属于该游戏）时页面底部浮出错误提示，下次保存成功后消失。
- 路径输入框下方即时提示：未设置 / 非完整路径 / 文件名不属于该游戏 / 找不到文件（输入框失去焦点时检查）。不合法的路径会被保存拒绝（底部错误提示），文件不存在则允许保存。
## 5. 应用设置抽屉

右上齿轮打开，**覆盖整个窗口（含标题栏）**，不是设置页，也不是左右分栏。

### 5.1 形态

- 从右侧滑入覆盖主页，宽 480，圆角 20；主页位置和背景构图不变。
- 遮罩铺满整个窗口（含标题栏），使整窗一起压暗；抽屉内容整体下移到标题栏下方，关闭按钮不会贴着系统窗口按钮。
- 关闭：点关闭按钮、点遮罩、再点齿轮或按 `Esc`。遮罩阻断下方主页的点击。

### 5.2 设置项与保存

- **设置改动即保存，没有保存按钮。**
- **点击关闭按钮时**（下拉三选一）：退出前确认 / 最小化到系统托盘 / 直接退出（详见第 6 节）。
- **游戏启动后**（下拉）：保持窗口不变 / 最小化主窗口（游戏进入运行状态后才生效，启动失败不会最小化）。
- **调试模式**（开关）：在主页显示启动与注入状态条；也可用环境变量 `SPARXIE_DEBUG=1` 开启。
- **数据与诊断**：打开配置目录、打开日志目录、导出脱敏诊断包（仅日志与环境信息，不含 config.json，写入数据目录下的 `diagnostics\`）。
- **关于**：版本号和“打开程序目录”。

### 5.3 不属于应用设置的内容

以下全部属于游戏设置（每个游戏各自保存）：名称、游戏路径、FPS 解锁、目标/后台 FPS、进程优先级、原神档位映射与触控 UI 缩放。同样不提供“启用触控”开关。

## 6. 关闭行为与托盘

“点击关闭按钮时”有三种行为：

- **退出前确认**：弹窗“退出 Sparxie？——退出后会关闭启动器，已启动的游戏继续运行”，带复选框“记住本次选择，下次不再询问”，按钮：退出 / 最小化到托盘 / 取消（默认取消）。勾选后点“退出”或“最小化到托盘”，会把设置里的“点击关闭按钮时”改成对应的行为（直接退出 / 最小化到托盘），之后不再询问；点“取消”不记住。想恢复询问，到应用设置里改回“退出前确认”；
- **最小化到系统托盘**：关闭窗口只是隐藏；托盘图标左键（单击/双击）恢复窗口，右键菜单有“显示 Sparxie / 退出”；
- **直接退出**。

**托盘图标始终显示**（启动后即出现，退出应用才移除），与上面的关闭行为无关。托盘图标从 ico 里按系统小图标尺寸取帧。

主程序退出时，隐藏的 Broker 随之退出；已经进入 Running 的会话由 SessionHost 独立持有，继续运行到游戏退出（触屏、退出后恢复分辨率都照常），不再能从启动器调整帧率；游戏退出后 Host 自行结束。启动中（未 Running）退出启动器则取消这次启动。

## 7. 数据边界

```text
config.json         唯一配置文件：schemaVersion / selectedProfileId / profiles[] / desktop{ selectedGame, lastProfileByGame, closeAction, debugMode, theme(预留) }
logs/               desktop.log、broker-*.log、host-*.log（Broker/Host 日志含会话事件：阶段、错误码、消息）
cache/backgrounds/  背景图与游戏图标缓存
```

- 以上全部放在**数据根目录**：程序目录；发布包采用“壳启动器 + `app-<版本>\`”布局（见第 10 节）时放在 `app-*` 的**上一级**，这样旧版本目录被清理时数据不丢。程序目录不可写时才回退到 `%LOCALAPPDATA%\Sparxie`。
- `lastProfileByGame` 只用于让“点游戏标题”落到可预期的配置，当前全局选中配置仍与 `selectedProfileId` 保持一致。

## 8. 触屏交互基线

- 主要点击目标 ≥ 48px：设置/数值控件 48，Flyout 配置按钮 48，游戏卡与 Flyout 行 56～68，设置行 64。
- 设置齿轮可见 44px；返回按钮 44px 高、带文字。
- 不依赖 16～20px 的小图标作为唯一命中区域；整行可点。
- 数值输入不依赖细 Slider。
- `Esc`：关闭设置抽屉、从设置页返回主页；用按键事件实现，不使用 `KeyboardAccelerator`（后者会让各控件的 tooltip 出现“Esc”）。

## 9. WinUI 3 视觉方向

- 深色玻璃风格：统一令牌——面板（深色半透明）、卡片（淡白半透明）、描边、弱化文字；圆角三档（面板 20 / 卡片 14 / 胶囊 28）。
- 游戏卡与启动状态条使用亚克力；不堆叠多层不同深度的灰：Flyout 只保留“面板深色”和“激活项”两个层次。
- 系统窗口按钮统一白色图标，悬停/按下给半透明白底，顶部叠一层压暗渐变，亮背景上也能看清。
- 背景主元素优先，UI 固定在左下、右下、右上。

## 10. 打包与启动

发布包采用“壳启动器 + 版本目录”布局：

```text
Sparxie\
  Sparxie.exe          约 160KB 的原生壳，按 version.ini 启动本体，启动后清理旧版本目录
  version.ini          exe_path=app-<版本>\Sparxie.Desktop.exe
  app-<版本>\          Desktop、Broker、SessionHost、原生 DLL、ZZZ Runtime、许可证
  config.json / logs\ / cache\   运行后生成在根目录
```

更新只需放入新的 `app-<版本>` 并修改 `version.ini`。
