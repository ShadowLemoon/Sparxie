# Sparxie 桌面端 GUI / 触屏交互设计

> 状态：与当前实现同步（2026-11）。本文描述桌面端**已经实现**的行为；尚未实现的内容集中写在最后一节“待办”。
>
> 目标：基于 WinUI 3 的桌面 GUI，面向触屏设备的极简启动器；启动配置与界面偏好存放在同一个 `config.json`。

## 1. 产品定位

Sparxie 不是传统的“游戏门户”或“功能面板”，而是面向 Windows 触屏设备的极简启动器。

核心原则：

- **触屏优先**：三款游戏均以触屏初始化成功作为启动成功硬条件，界面中不存在“关闭触控”这一概念。
- **背景主视觉优先**：界面尽量贴边、留白，不遮挡背景主体；主题色随背景图变化。
- **启动路径最短**：切游戏、切配置、启动游戏都在一到两次触摸内完成。
- **单配置时不出现“配置/Profile”概念**：大多数人每个游戏只有一套配置，界面上只有“游戏设置”；有多套（如国服/国际服）时才出现配置切换。
- **真实映射现有模型**：设置项直接对应 `GameProfile` / `HoyoProfileSettings`，不虚构不存在的概念。
- **数据合一**：只有一个 `config.json`：启动配置（schemaVersion / selectedProfileId / profiles[]）与可选的 `desktop` 段（界面偏好）同文件保存，没有单独的 GUI 配置文件。

## 2. 信息架构

只有三种界面状态：

1. **主页（Launch）**
2. **游戏设置页**（按游戏分开，一个游戏一页）
3. **应用设置抽屉**（覆盖式 Side Panel）

分工固定：

- 左下：**游戏卡**——同时承担“当前游戏 + 当前配置”的显示与切换，右侧齿轮进入当前游戏的设置；
- 右下：**启动游戏**（唯一主操作）；
- 右上：应用设置（圆形齿轮）；
- 顶部：只有窗口标题与系统窗口按钮，**没有游戏标签**。

## 3. 启动主页

### 3.1 布局

```text
┌────────────────────────────────────────────────────────────┐
│ ▷ Sparxie                                       ⚙   ─ □ × │
│                                                            │
│                       背景主视觉                            │
│                                                            │
│ ┌──────────────────────────┐                ┌────────────┐ │
│ │ [图标] 绝区零 · 国际服  ▴ │⚙│              │ 启动游戏 │ │
│ └──────────────────────────┘                └────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- **游戏卡**：固定宽度 380、高 68，亚克力半透明底，圆角 20。左侧切换区显示游戏图标（40px）与文字，单配置时只写游戏名（“原神”），多配置时写“游戏 · 配置名”；右侧 68×68 的齿轮进入当前游戏设置。
- **启动游戏按钮**：320×68 的大胶囊，填充色取当前游戏背景主色的色相（柔色：饱和度约 0.42、明度约 0.97），深色粗体字；悬停变深一档（并按悬停色重新选字色以保证对比度），按下再深一档。
- **设置齿轮**：右上角 44px 圆形玻璃按钮，位于系统窗口按钮左侧并留出间距。
- **启动状态条**：仅在“调试模式”下显示在启动按钮上方，列出启动/注入各阶段与失败原因；平时隐藏，失败原因仍写入日志。

### 3.2 游戏卡与切换 Flyout

点击游戏卡左侧切换区，向上展开 Flyout（宽 344，圆角 20，亚克力）：

- 三个游戏各占一个“块”：标题行（图标 + 名称，行高 56）；该游戏有**多套配置**时，标题下平铺配置按钮（高 48，胶囊）；单配置的游戏不显示配置按钮。
- **配色规则只有两种**：当前激活项用**主题色**（单配置游戏是整行，多配置游戏是对应的配置按钮），其余为灰色/描边；**不使用对勾**。
- 点击游戏标题 = 切到该游戏**上次使用的配置**（记住的配置在 Flyout 里以浅灰底提示，保证点之前就能预见结果；记忆保存在 `config.json` 的 `desktop` 段，重启后保留，没有记录时取该游戏第一套配置）。点击某个配置按钮 = 同时切游戏和配置。
- **切换后 Flyout 保持打开**，方便连续比较并观察背景与主题色的变化；点 Flyout 外部或按 `Esc` 关闭。

### 3.3 背景与主题色

- 背景来自官方启动器接口（HoYoPlay `getAllGameBasicInfo` 的 backgrounds），按**图片 URL 的哈希**命名缓存到 `cache/backgrounds/`，并记录每个游戏“当前背景”指针；官方换图即换文件名，不覆盖旧文件。
- 切换游戏时**先同步显示缓存**，再在后台检查官方是否换图；官方地址在内存中缓存 10 分钟；网络失败回退该游戏上次的缓存，再没有则退回纯色背景。
- 切换时新图叠在旧图上交叉淡入（约 450ms）。
- **主题色**：取背景图的平均色，保留其色相与明度（V），饱和度固定 0.6；平均色接近无彩色时回退默认蓝。主题色驱动激活项、启动按钮，并覆盖系统强调色（`SystemAccentColor` 及亮/暗变体），其他强调色控件随之变色。暗背景得到偏暗的主题色，亮背景才亮。

### 3.4 游戏路径异常与运行状态

- **路径异常**：当前配置的 EXE 未设置、找不到文件、文件名不属于该游戏时，启动按钮上方出现提示条（黄色描边），并带“定位游戏”按钮，直达当前游戏的设置页。检查规则与设置页、配置域层一致（`ExecutablePathCheck`）。
- **运行状态**：会话启动成功后，该游戏的启动按钮禁用并显示“运行中”；收到终态事件（退出 / 失败 / Host 崩溃）后恢复。启动过程中显示“启动中…”。按游戏区分，其他游戏仍可启动。
- 已知边界：桌面端重启时不会检测此前已在运行的游戏，按钮仍可点，点了会被会话边界以“对应游戏已在运行”拒绝。

## 4. 游戏设置页

设置页**按游戏分开**，标题为“{游戏} 设置”，左上是带文字的“‹ 返回”玻璃胶囊（在页面内容区，不在标题栏；`Esc` 同样返回）。

### 4.1 布局

两栏，宽度全程拉伸，不因折叠、切换配置或切换游戏而改变：

```text
┌ ‹ 返回  原神 设置 [配置A][配置B]            ＋ 添加配置 ┐
│ ┌ 游戏 ──────────┐ ┌ 帧率 ────────────────────────┐ │
│ │ 名称（多配置时）│ │ 目标帧率   说明     [开关][−120+]│ │
│ │ 游戏 EXE  [📁] │ │ 后台帧率   说明     [开关][−10 +]│ │
│ │ 进程优先级      │ │ 帧率档位映射（原神）           │ │
│ └────────────────┘ └──────────────────────────────┘ │
│ ┌ 触控 UI 缩放（原神）┐                                │
│ （没有保存条；修改后自动保存，出错时底部浮出提示） │
└──────────────────────────────────────────────────────┘
```

- **左栏（固定 380）**：游戏相关——名称（仅多配置时显示）、游戏 EXE（带浏览）、进程优先级；原神再加一张“触控 UI 缩放”卡。
- **右栏**：帧率。开关与数值合并为一行；开关关闭时只**禁用**对应数值，不隐藏，因此高度宽度都不变；原神多一行“帧率档位映射”（跟随游戏内档位 + 30/60 档数值）。
- **绝区零**没有帧率与优先级设置：只显示一张铺满宽度的“游戏”卡（名称、EXE），不留空的右栏。
- **配置 ID 不在界面出现**，新建时自动生成不重复的 ID。

### 4.2 多配置

- 只有一套配置时没有任何列表，页面就是一张表单。
- 同一游戏有多套时，标题行出现**横向配置切换条**。
- 标题行右侧常驻“＋ 添加配置”，点击**立即创建并保存**一套新配置（自动取不重复的 ID 与名称），随后在表单里补全。
- 标题行右侧“⋯”菜单：**复制当前配置**（复制路径与全部设置，名称加“副本”，立即保存）；**删除当前配置**（仅多配置时出现，点击先弹确认），不再占用表单位置。
- 一个游戏的最后一套配置不可删除（避免出现空配置）。

### 4.3 数值与触屏控件

- FPS：10～1000；原神触控 UI 缩放：100%～500%。
- 数值一律用 `[−] 值 [+]` 控件（按钮 48×48，数值框 18 号字、垂直居中），不依赖细 Slider。
- 文本框、下拉框统一 16 号字、最小高度 48、文字垂直居中。

### 4.4 保存策略

**自动保存，没有保存按钮和未保存状态**：任何字段修改后约 0.5 秒落盘（连续输入只写一次）；切换游戏、返回主页、关闭窗口前会先立即落盘。

- 保存成功时底部短暂提示“修改已保存”（2 秒后消失）；失败（如路径不属于该游戏）时页面底部浮出错误提示，下次保存成功后消失。
- 路径输入框下方即时提示：未设置 / 非完整路径 / 文件名不属于该游戏 / 找不到文件（输入框失去焦点时检查）。不合法的路径会被保存拒绝（底部错误提示），文件不存在则允许保存。
## 5. 应用设置抽屉

右上齿轮打开，**覆盖整个窗口（含标题栏）**，不是设置页，也不是左右分栏。

### 5.1 形态

- 从右侧滑入覆盖主页，宽 480，圆角 20；主页位置和背景构图不变。
- 遮罩铺满整个窗口（含标题栏），使整窗一起压暗；抽屉内容整体下移到标题栏下方，关闭按钮不会贴着系统窗口按钮。
- 关闭：点关闭按钮、点遮罩、再点齿轮或按 `Esc`。遮罩阻断下方主页的点击。

### 5.2 设置项与保存

- **设置改动即保存，没有保存按钮。**
- **点击关闭按钮时**（下拉三选一）：退出前确认 / 最小化到系统托盘 / 直接退出（详见第 6 节）。
- **游戏启动后**（下拉）：保持窗口不变 / 最小化主窗口（游戏进入运行状态后才生效，启动失败不会最小化）。
- **调试模式**（开关）：在主页显示启动与注入状态条；也可用环境变量 `SPARXIE_DEBUG=1` 开启。
- **数据与诊断**：打开配置目录、打开日志目录、导出脱敏诊断包（仅日志与环境信息，不含 config.json，写入数据目录下的 `diagnostics\`）。
- **关于**：版本号、许可证与第三方 / Runtime 声明位置说明，以及“打开程序目录”。

### 5.3 不属于应用设置的内容

以下全部属于游戏设置（每个游戏各自保存）：名称、游戏路径、FPS 解锁、目标/后台 FPS、进程优先级、原神档位映射与触控 UI 缩放。同样不提供“启用触控”开关。

## 6. 关闭行为与托盘

“点击关闭按钮时”有三种行为：

- **退出前确认**：弹窗“退出 Sparxie？——退出后会关闭启动器，已经启动的游戏不受影响”，按钮：退出 / 最小化到托盘 / 取消（默认取消）；
- **最小化到系统托盘**：关闭窗口只是隐藏；托盘图标左键（单击/双击）恢复窗口，右键菜单有“显示 Sparxie / 退出”；
- **直接退出**。

在确认框里临时选“最小化到托盘”时，托盘图标只在窗口隐藏期间存在，窗口恢复后即移除；设置里选“托盘”则图标常驻。旧版“退出前确认”开关自动迁移：确认 → 询问，不确认 → 直接退出。

主程序退出时，隐藏的 Broker 随之退出；已经进入 Running 的游戏进程不受影响。

## 7. 数据边界

```text
config.json         唯一配置文件：schemaVersion / selectedProfileId / profiles[] / desktop{ selectedGame, lastProfileByGame, closeAction, debugMode, theme(预留) }
logs/               desktop.log、broker-*.log、host-*.log（Broker/Host 日志含会话事件：阶段、错误码、消息）
cache/backgrounds/  背景图与游戏图标缓存
```

- 以上全部放在**数据根目录**：程序目录；发布包采用“壳启动器 + `app-<版本>\`”布局（见第 10 节）时放在 `app-*` 的**上一级**，这样旧版本目录被清理时数据不丢。程序目录不可写时才回退到 `%LOCALAPPDATA%\Sparxie`。
- `lastProfileByGame` 只用于让“点游戏标题”落到可预期的配置，当前全局选中配置仍与 `selectedProfileId` 保持一致。

## 8. 触屏交互基线

- 主要点击目标 ≥ 48px：设置/数值控件 48，Flyout 配置按钮 48，游戏卡与 Flyout 行 56～68，设置行 64。
- 设置齿轮可见 44px；返回按钮 44px 高、带文字。
- 不依赖 16～20px 的小图标作为唯一命中区域；整行可点。
- 数值输入不依赖细 Slider。
- `Esc`：关闭设置抽屉、从设置页返回主页；用按键事件实现，不使用 `KeyboardAccelerator`（后者会让各控件的 tooltip 出现“Esc”）。

## 9. WinUI 3 视觉方向

- 深色玻璃风格：统一令牌——面板（深色半透明）、卡片（淡白半透明）、描边、弱化文字；圆角三档（面板 20 / 卡片 14 / 胶囊 28）。
- 游戏卡与启动状态条使用亚克力；不堆叠多层不同深度的灰：Flyout 只保留“面板深色”和“激活项”两个层次。
- 系统窗口按钮统一白色图标，悬停/按下给半透明白底，顶部叠一层压暗渐变，亮背景上也能看清。
- 背景主元素优先，UI 固定在左下、右下、右上。

## 10. 打包与启动

发布包采用“壳启动器 + 版本目录”布局：

```text
Sparxie\
  Sparxie.exe          约 160KB 的原生壳，按 version.ini 启动本体，启动后清理旧版本目录
  version.ini          exe_path=app-<版本>\Sparxie.Desktop.exe
  app-<版本>\          Desktop、Broker、SessionHost、原生 DLL、ZZZ Runtime、许可证
  config.json / logs\ / cache\   运行后生成在根目录
```

更新只需放入新的 `app-<版本>` 并修改 `version.ini`。

## 11. 非目标

当前桌面 GUI 不包含：下载管理中心、账号中心、游戏新闻/活动门户、游戏时长统计、磁盘占用 Dashboard、Runtime 管理 Dashboard、关闭触屏功能。
